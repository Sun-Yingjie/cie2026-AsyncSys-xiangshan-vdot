# 面积与时序评估：vqdot 的硬件开销

**团队**：AsyncSys
**方法**：用 Design Compiler（V-2023.12）对 vqdot 新增的运算单元 VDot64b 做逻辑综合，工艺为 SMIC 0.18um（典型角 tt_v1.8_25c）。综合不依赖 FPGA，作为面积/时序的定量评估。

> 说明：工艺节点只影响绝对值，不影响"vqdot 新增了什么、开销多大"的结论。VDot64b 是一个结构简单、自包含的组合+两级流水单元，其面积构成（乘法器/加法树/寄存器）在任何工艺下比例一致。

---

## 1. 综合结果

| 指标 | 数值 |
|---|---|
| **总面积** | **40,748 µm² ≈ 5,414 个 NAND2 等效门** |
| 组合逻辑面积 | 35,645 µm²（4,736 门） |
| 时序逻辑面积 | 5,103 µm²（678 门，129 个触发器） |
| 单元总数 | 2,441 |
| 关键路径 | **1.77 ns**（2 ns 周期约束下 slack MET，0.01 ns） |

> NAND2 参考单元 NAND2UHDV1 面积 7.5264 µm²。

## 2. 面积构成分解

VDot64b 处理 64bit（2 个 32bit 元素，每元素 4 个 int8），硬件构成：

| 组成 | 数量 | 面积 (µm²) | 等效门 |
|---|---|---|---|
| INT8 乘法器 | 8 | 27,125 | 3,604 |
| 加法树（含符号扩展） | — | 8,520 | 1,132 |
| 两级流水寄存器 | 129 FF | 5,103 | 678 |
| **合计** | | **40,748** | **5,414** |

单个 8×8 有符号乘法器（综合参照）面积 3,390 µm²（约 450 门），8 个约 27,125 µm²，与分解吻合。

## 3. 开销分析：面积小、收益大

- **新增硬件集中且有限**：vqdot 只需要在向量运算单元中新增一个 VDot64b（约 5.4k 门）。译码/解码/重命名等改动是复用现有通路（仅在译码表加一个 BitPat、在"依赖旧值"清单加三条指令），不产生可观的额外面积。
- **关键路径短**：8bit 乘法器 + 两级加法树仅 1.77 ns，在 0.18um 这种成熟工艺下都能满足 2ns 周期，在更先进工艺（香山实际使用的 12/14nm）下余量极大，不会成为频率瓶颈。
- **面积换来的收益**：
  - 纯计算 **4.62x**；
  - 真实 GEMV 线性层端到端 **2.82x**；
  - 点积微基准端到端 1.63x。

即约 5.4k 门的一次性面积开销，换来点积/线性层这一 LLM 核心计算 2.8x~4.6x 的加速，性价比高。

## 4. 对比基线的本质

标准 RVV 实现点积不需要"额外的乘法器"——它复用 VPU 已有的宽元素乘法器，但要付出：
- 指令数：10 条 vs 1 条；
- 跨元素归约：3 次 `slide/gather` 数据搬运（这些置换通路本身也有面积与端口开销）；
- 多级 `vadd` 串行收敛。

vqdot 用一个专用加法树（约 1.1k 门的加法树 + 复用乘法器）把"跨元素归约"在数据通路内一拍完成，省去了运行时反复搬运和串行收敛——这正是"以少量面积换大幅延迟下降"的典型架构权衡。

## 5. 复现方法

综合脚本与设计在服务器 `$VDOT_HOME/syn_vdot/`：

```bash
# VDot64b 综合（约 1-2 分钟）
export SNPSLMD_LICENSE_FILE=28001@lzdx01
export PATH=/mnt/edatools/synopsys/syn/V-2023.12-SP3/bin:$PATH
cd $VDOT_HOME/syn_vdot
dc_shell -f syn2.tcl      # 用普通 compile；报告输出 area.rpt / timing.rpt
```

> 注：`compile_ultra` 在本机环境会在 Analyzing 阶段异常退出（环境问题，非设计问题），改用普通 `compile` 可正常完成，面积/时序结论不受影响。
